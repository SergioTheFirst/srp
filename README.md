# SRP — раннее предупреждение отказов парка Windows-ПК

[![Лицензия](https://img.shields.io/badge/лицензия-PolyForm%20Noncommercial%201.0.0-blue.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)
[![Демо](https://img.shields.io/badge/демо-j--space.ru-0ea5e9.svg)](https://j-space.ru)

**SRP — это self-hosted система раннего предупреждения отказов парка Windows-компьютеров.**
Она замечает деградацию машины **до** отказа: умирающий диск, деградирующую память или
зависший принтер видно раньше, чем это заметит пользователь. Тонкий агент без
единой сторонней зависимости собирает телеметрию (SMART, журналы событий, BSOD,
производительность, сеть, печать), сервер на FastAPI + SQLite копит историю и считает
объяснимые оценки здоровья, а живой дашборд показывает весь парк: компьютеры,
принтеры, карту сети и учёт печати.

[![Список парка: индекс здоровья, состояние и главный фактор риска по каждой машине](docs/img/fleet.png)](https://j-space.ru)

> **Это публичный срез.** Репозиторий — публикация одним коммитом кода из приватного
> репо с историей 800+ коммитов; история разработки здесь не сохранена намеренно.

## Как это работает

**Тонкий агент / толстый сервер.** Агент ничего не решает — он собирает телеметрию
(SMART, журналы событий, производительность, сеть, печать, сертификаты) и шлёт её
серверу; вся аналитика — на сервере.

```mermaid
flowchart LR
    A["Агент<br/>чистый stdlib · PowerShell 5.1"] -- "HTTP POST /api/v1/ingest" --> S["Сервер<br/>FastAPI + SQLite"]
    S -- "SNMP · IPP<br/>(только RFC1918)" --> N["Принтеры и сеть"]
    E["Инженер"] --> W["Дашборд<br/>риск · доверие к данным · прогнозы"]
    W --> S
```

| Слой | Технологии | Что делает |
|---|---|---|
| **Агент** | Windows, Python 3.9+, только стандартная библиотека — ноль pip-пакетов на рабочих машинах | Собирает телеметрию через CIM/PowerShell 5.1 (языконезависимо), отправляет конвертом раз в 5–15 минут |
| **Сервер** | FastAPI + SQLite, self-hosted, разворачивается одной командой | Валидирует, копит историю, считает риск и доверие к источникам |
| **Дашборд** | Серверный рендер (Jinja2), без сборки JS | Три координаты здоровья вместо одного числа, байесовский риск по классам отказа с объяснением каждого фактора, прогноз заполнения диска и расходников по SMART/тонеру, карта сети по SNMP/LLDP |

## Чем это отличается от обычного мониторинга

Классический мониторинг отвечает на вопрос «что сломано сейчас» и срабатывает по
порогам. SRP отвечает на другой вопрос: «что сломается следующим и когда».

| Вопрос | Классический мониторинг | SRP |
|---|---|---|
| На что отвечает | Что сломано прямо сейчас | Что сломается следующим и когда |
| Как срабатывает | Порог: диск на 90 % — авария | Тренд и срок до выхода за границу |
| Оценка машины | Одно число или набор графиков | Три независимые координаты: повреждения, устойчивость, наблюдаемость |
| Если данные врут | Считает их как есть | Источник теряет доверие и не участвует в выводах |
| Что ставится на ПК | Агент с зависимостями или опрос извне | Агент на чистой стандартной библиотеке, ноль pip-пакетов |

## Вопросы и ответы

### Что нужно, чтобы попробовать?

Python 3.9 или новее на машине, где будет сервер, и права администратора на
компьютерах, куда ставится агент. Сервер разворачивается из архива одной командой,
агент — установщиком, который спрашивает только адрес сервера. Ничего облачного не
требуется. Бесплатная версия принимает до трёх компьютеров.

### Уходит ли собранная телеметрия наружу?

Нет. Сервер разворачивается у вас, и данные никуда не отправляются. Серийные номера
дисков агент хеширует ещё до отправки — наружу уходит только хеш. Из сетевых адресов
передаются исключительно частные диапазоны локальной сети. Приватные ключи
сертификатов не собираются в принципе, только метаданные срока действия.

### Работает ли это на русской Windows?

Да, и это проверено на живых машинах. Агент читает счётчики через CIM и разбирает
только числа и английские имена перечислений — локализованный текст в расчёты не
попадает. Установщик тоже не зависит от языка системы: права назначаются по
идентификаторам, а не по именам групп.

### Что именно предсказывается?

Ресурс SSD и заполнение диска — по SMART и истории записи; дата исчерпания тонера —
по счётчикам SNMP. Для показателей без физической границы отказа (например,
троттлинг CPU) показывается только направление тренда: выдумывать срок там, где его
нет, система не станет.

## Быстрый старт

Нужен Python 3.9+.

Если сервер скачан архивом `srp-server-free.zip` из раздела Releases — распакуйте
и запустите `install-server.bat`: он создаст `.venv`, поставит зависимости и
скажет, чем запускать. Ручной путь — ниже.

```powershell
# сервер
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m server.main
# дашборд: http://<IP-сервера>:8000/
```

```powershell
# агент — на любой Windows-машине парка (или проверка на текущей)
python -m client.agent --server http://<IP-сервера>:8000 --once   # разовый проход
python -m client.agent                                            # постоянная работа
```

Для боевого раската — самодостаточный `setup.exe` со страницы **Releases** этого
репозитория (агент собран PyInstaller'ом, сам код агента остаётся чистым stdlib):

```bat
setup.exe --server http://<IP-сервера>:8000
```

Быстрая проверка всей цепочки без сети: `python smoke.py`.

## Обнаружение сети

Пассивное обнаружение (`netdisco.passive_enabled`) работает из коробки — сервер
собирает ARP/SNMP/LLDP-данные, которые агенты и так видят в своей подсети.

**Активное сканирование (`active_scan`) в этой сборке выключено.** Активный скан
пробует диапазоны IP той сети, где установлен сервер, — включать его по умолчанию
для незнакомой сети было бы неправильно: письменное разрешение владельца на активный
скан покрывает только его собственную локальную сеть, а не сеть человека, который
поставит SRP себе. Это тот же принцип, что и с автообновлением и мульти-организациями —
то, что требует ответственности за чужую инфраструктуру, не включено по умолчанию.

Включается сознательно, одной строкой: `netdisco.active_scan: true` и
`printers.active_scan: true` в `server/config.json`, затем перезапуск сервера — только
в своей собственной сети.

## Ограничения бесплатной версии

- **До 3 компьютеров** в парке — `/api/v1/ingest` отвечает `403` сверх лимита.
- **Без автообновления агентов** — массовый выкат новых версий на весь парк одной
  командой есть только в полной версии.
- **Без мульти-организаций** — единый парк без разделения по организациям/отделам.

### Полная версия

Автообновление парка, снятие лимита в 3 компьютера, мульти-организации,
приоритетная поддержка — [j-space.ru/#full](https://j-space.ru/#full).
