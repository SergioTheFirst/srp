# J-Space — раннее предупреждение отказов парка Windows-ПК

[![Лицензия](https://img.shields.io/badge/лицензия-MIT-blue.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)
[![Демо](https://img.shields.io/badge/демо-j--space.ru-0ea5e9.svg)](https://j-space.ru)

**J-Space — это self-hosted система раннего предупреждения отказов парка Windows-компьютеров.**
Она замечает деградацию машины **до** отказа: умирающий диск, деградирующую память или
зависший принтер видно раньше, чем это заметит пользователь. Тонкий агент без
единой сторонней зависимости собирает телеметрию (SMART, журналы событий, BSOD,
производительность, сеть, печать), сервер на FastAPI + SQLite копит историю и считает
объяснимые оценки здоровья, а живой дашборд показывает весь парк: компьютеры,
принтеры, карту сети и учёт печати.

[![Список парка: индекс здоровья, состояние и главный фактор риска по каждой машине](docs/img/fleet.png)](https://j-space.ru)

> **Это публичный срез.** Репозиторий — публикация одним коммитом кода из приватного
> репо с историей 800+ коммитов; история разработки здесь не сохранена намеренно.
> Лицензия — [MIT](LICENSE): пользуйтесь, меняйте и распространяйте свободно,
> в том числе коммерчески.

## Как это работает

**Тонкий агент / толстый сервер.** Агент ничего не решает — он собирает телеметрию
(SMART, журналы событий, производительность, сеть, печать, сертификаты) и шлёт её
серверу; вся аналитика — на сервере.

```mermaid
flowchart LR
    A["Агент<br/>чистый stdlib · PowerShell 5.1"] -- "HTTP POST /api/v1/ingest" --> S["Сервер<br/>FastAPI + SQLite"]
    S -- "SNMP · IPP<br/>(только RFC1918)" --> N["Принтеры и сеть"]
    E["Инженер"] --> W["Дашборд<br/>риск · доверие к данным · прогнозы"]
    W --> S
```

| Слой | Технологии | Что делает |
|---|---|---|
| **Агент** | Windows, Python 3.9+, только стандартная библиотека — ноль pip-пакетов на рабочих машинах | Собирает телеметрию через CIM/PowerShell 5.1 (языконезависимо), отправляет конвертом раз в 5–15 минут |
| **Сервер** | FastAPI + SQLite, self-hosted, разворачивается одной командой | Валидирует, копит историю, считает риск и доверие к источникам |
| **Дашборд** | Серверный рендер (Jinja2), без сборки JS | Три координаты здоровья вместо одного числа, байесовский риск по классам отказа с объяснением каждого фактора, прогноз заполнения диска и расходников по SMART/тонеру, карта сети по SNMP/LLDP |

## Чем это отличается от обычного мониторинга

Классический мониторинг отвечает на вопрос «что сломано сейчас» и срабатывает по
порогам. J-Space отвечает на другой вопрос: «что сломается следующим и когда».

| Вопрос | Классический мониторинг | J-Space |
|---|---|---|
| На что отвечает | Что сломано прямо сейчас | Что сломается следующим и когда |
| Как срабатывает | Порог: диск на 90 % — авария | Тренд и срок до выхода за границу |
| Оценка машины | Одно число или набор графиков | Три независимые координаты: повреждения, устойчивость, видимость |
| Если данные врут | Считает их как есть | Источник теряет доверие и не участвует в выводах |
| Что ставится на ПК | Агент с зависимостями или опрос извне | Агент на чистой стандартной библиотеке, ноль pip-пакетов |

## Вопросы и ответы

### Что нужно, чтобы попробовать?

Python 3.9 или новее на машине, где будет сервер, и права администратора на
компьютерах, куда ставится агент. Сервер разворачивается из архива одной командой,
агент — установщиком, который спрашивает только адрес сервера. Ничего облачного не
требуется. Бесплатная версия принимает до трёх компьютеров.

### Уходит ли собранная телеметрия наружу?

Нет. Сервер разворачивается у вас, и данные никуда не отправляются. Серийные номера
дисков агент хеширует ещё до отправки — наружу уходит только хеш. Из сетевых адресов
передаются исключительно частные диапазоны локальной сети. Приватные ключи
сертификатов не собираются в принципе, только метаданные срока действия.

### Работает ли это на русской Windows?

Да, и это проверено на живых машинах. Агент читает счётчики через CIM и разбирает
только числа и английские имена перечислений — локализованный текст в расчёты не
попадает. Установщик тоже не зависит от языка системы: права назначаются по
идентификаторам, а не по именам групп.

### Что именно предсказывается?

Ресурс SSD и заполнение диска — по SMART и истории записи; дата исчерпания тонера —
по счётчикам SNMP. Для показателей без физической границы отказа (например,
троттлинг CPU) показывается только направление тренда: выдумывать срок там, где его
нет, система не станет.

## Быстрый старт

Нужен Python 3.9+.

Если сервер скачан архивом `srp-server-free.zip` из раздела Releases — распакуйте
и запустите `install-server.bat`: он создаст `.venv`, поставит зависимости и
запустит сервер — в трее появится значок J-Space (если он спрятался в скрытую
область — перетащите его на панель задач), включится автозапуск при входе в
Windows. Запустить вручную — `server_tray.bat` (`start_server.bat` — тот же сервер в
окне, для отладки; вместе их не запускайте). Всё в меню значка (правый щелчок), без
командной строки: дашборд, журнал, пароли для входа из интернета, резервная копия базы,
Caddy; батники — запасной путь. Ручной путь — ниже.

```powershell
# сервер
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m server.main
# дашборд: http://<IP-сервера>:8000/
```

```powershell
# агент — на любой Windows-машине парка (или проверка на текущей)
python -m client.agent --server http://<IP-сервера>:8000 --once   # разовый проход
python -m client.agent                                            # постоянная работа
```

Для установки на машины парка — архив `srp-agent-free.zip` со страницы **Releases**
этого репозитория: распакуйте и запустите `setup.exe` от администратора — мастер
спросит адрес сервера. Папка `payload` рядом с `setup.exe` — это сам агент (собран
PyInstaller'ом, код агента остаётся чистым stdlib). Тихая установка:

```bat
setup.exe --server http://<IP-сервера>:8000
```

Быстрая проверка всей цепочки без сети: `python smoke.py`.

## Просмотр из интернета

Дашборд можно смотреть из интернета, например с телефона: по личному паролю, только на
просмотр и без персональных данных (ФИО, телефоны, комментарии, пользователи печати
скрыты; имена компьютеров и карта сети видны). В локальной сети пароль не нужен, агенты
работают как прежде. Нужен статический внешний IP.

1. Роутер пробрасывает 443/TCP на сервер.
2. Меню значка сервера → «Вход из интернета (Caddy)…» (или `install-caddy.bat` в папке
   сервера двойным щелчком); Windows спросит права администратора. Скрипт спросит
   внешний IP сервера и имя учётной записи — пароль печатается один раз, передайте его
   лично. Остальное скрипт делает сам: скачивает
   [Caddy](https://caddyserver.com) (для 64-битной Windows — 2.11.9 со сверкой SHA-512; для
   32-битной — последняя сборка, без закреплённой версии и контрольной суммы),
   ставит его службой Windows `caddy` с правилом брандмауэра и ждёт сертификат
   Let's Encrypt на IP. Повторный запуск (например, сменился IP) заменяет установку.
   Ещё записи и новые пароли — меню значка → «Пароли для входа из интернета…» (запасной
   путь — `users.bat`, `users.bat -h`).

**Вручную** — если скрипт не подошёл. Нужен Caddy 2.11 или новее (2.10 не получает
сертификат на IP). Команды — в командной строке (cmd) от имени администратора.

1. Роутер пробрасывает 443/TCP на сервер; на сервере порт 443 свободен
   (`netstat -ano | findstr :443`).
2. В папку `C:\Program Files\Caddy\` — `caddy.exe` и `Caddyfile` из папки сервера (рядом
   с `start_server.bat`). Caddy для 64-битной Windows — `caddy_<версия>_windows_amd64.zip`
   с <https://github.com/caddyserver/caddy/releases>; для 32-битной —
   <https://caddyserver.com/download>, платформа «Windows 386», файл переименовать в
   `caddy.exe`.
3. В `Caddyfile` заменить `203.0.113.10` на внешний IP сервера в обеих строках —
   `default_sni` и адрес сайта: по IP браузер не называет сайт, а за пробросом роутера
   Caddy видит свой локальный адрес.
4. Брандмауэр и первый запуск — до строки `certificate obtained successfully`, затем
   Ctrl+C:

   ```bat
   netsh advfirewall firewall add rule name="J-Space Caddy 443" dir=in action=allow protocol=TCP localport=443 program="C:\Program Files\Caddy\caddy.exe"
   "C:\Program Files\Caddy\caddy.exe" run --config "C:\Program Files\Caddy\Caddyfile"
   ```

5. Служба Windows — стартует вместе с ПК, без прав администратора:

   ```bat
   sc.exe create caddy start= auto obj= "NT AUTHORITY\LocalService" password= "" binPath= "\"C:\Program Files\Caddy\caddy.exe\" run --config \"C:\Program Files\Caddy\Caddyfile\""
   sc.exe failure caddy reset= 86400 actions= restart/60000
   sc.exe start caddy
   ```

   Правка `Caddyfile` — `sc.exe stop caddy`, правка, `sc.exe start caddy`.
6. Учётная запись — меню значка сервера → «Пароли для входа из интернета…» (или
   `users.bat add <имя>` в папке сервера): пароль показывается один раз, передайте его
   лично. Там же новый пароль, отключение и выход на всех устройствах (`users.bat -h`).

Проверка с мобильного интернета: `https://<IP>` открывается без предупреждения о
сертификате и просит войти, `http://<IP>:8000/` отвечает 404. Прокси на порт 8000 не
направляйте: Caddy ходит на `127.0.0.1:8001`, так уже в шаблоне.

**Запасные пути** — если сертификата нет (ошибки — в консоли Caddy или в журнале службы
`C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\Caddy\caddy.log`), по порядку:
1. Ошибки `tls-alpn-01` → пробросить ещё 80/TCP (порт 80 на сервере свободен), добавить
   правило брандмауэра из шага 4 с `name="J-Space Caddy 80"` и `localport=80`, удалить из
   `Caddyfile` строку `disable_http_challenge`: Let's Encrypt проверит сервер по порту 80.
2. Сертификат на IP всё равно не выдан → бесплатное DNS-имя на ваш статический IP (у
   провайдера или в сервисе динамического DNS, например DuckDNS): имя вместо IP в обеих
   строках `Caddyfile`, вход — `https://<имя>`.
3. Ничего не помогло → свой сертификат Caddy: блок `tls { … }` заменить строкой
   `tls internal`, в верхний блок добавить строку `skip_install_trust`. Корневой
   сертификат службы
   (`C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\Caddy\pki\authorities\local\root.crt`)
   установить доверенным на каждое устройство, с которого смотрят, иначе браузер
   предупреждает. Осторожно: такой корень подтверждает устройству любой сайт, а его ключ
   (`root.key` в той же папке) лежит на сервере — кто его получит (взломанный Caddy,
   администратор сервера, копия диска), подделает этим устройствам хоть банк. Ставить на
   как можно меньше устройств; заработал путь 1 или 2 — удалить корень с них.

## Обнаружение сети

Пассивное обнаружение (`netdisco.passive_enabled`) работает из коробки — сервер
собирает ARP/SNMP/LLDP-данные, которые агенты и так видят в своей подсети.

**Активное сканирование (`active_scan`) в этой сборке выключено.** Активный скан
пробует диапазоны IP той сети, где установлен сервер, — включать его по умолчанию
для незнакомой сети было бы неправильно: письменное разрешение владельца на активный
скан покрывает только его собственную локальную сеть, а не сеть человека, который
поставит J-Space себе. Это тот же принцип, что и с автообновлением и мульти-организациями —
то, что требует ответственности за чужую инфраструктуру, не включено по умолчанию.

Включается сознательно, одной строкой: `netdisco.active_scan: true` и
`printers.active_scan: true` в `server/config.json`, затем перезапуск сервера — только
в своей собственной сети.

## Если у вас уже стоит Zabbix

J-Space его не заменяет. Zabbix отвечает на вопрос «что сломано сейчас»; J-Space считает то,
чего у Zabbix нет, — состояние машины по тренду и истории и срок реакции — и отдаёт его туда
обычными значениями элементов данных. Дальше работают привычные триггеры, действия и эскалации.

Принцип: **в Zabbix уходит вывод, а не данные.** Всё, что помогает понять «почему»,
остаётся в J-Space — там и смотрят. Наружу уезжает ровно четыре значения на компьютер:

| Ключ | Значение |
|---|---|
| `srp.state` | состояние: `h0` норма … `h4` предотказ, либо `unknown` |
| `srp.risk` | 0…100, больше — хуже |
| `srp.days_left` | срок реакции в сутках (по состоянию) или прогноз по тренду, если он короче |
| `srp.reason` | главный фактор одной фразой, без идентификаторов |

Плюс один ключ на сам сервер J-Space — `srp.last_run`, время последнего расчёта, чтобы
Zabbix видел, что J-Space жив. Все элементы — типа «Zabbix trapper», готовые шаблоны
лежат в `docs/zabbix/srp_template.yaml`.

Включается одной настройкой — адресом Zabbix в `server/config.json`:

```json
"zabbix": { "server": "10.0.0.5" }
```

Непустой адрес и означает «включено»; перезапускать сервер не нужно. Проверить
настройку до включения:

```
python -m server.zabbix.check --server 10.0.0.5   # чек-лист по пунктам
python -m server.zabbix.check --list-hosts        # CSV имён узлов под массовый импорт
python -m server.zabbix.check --check-hosts       # какие узлы Zabbix ещё не знает
```

Недоступный Zabbix на работу J-Space не влияет: у отправки жёсткие таймауты, ошибка
гасится в фоновом цикле и не доходит ни до приёма телеметрии, ни до скоринга.
Наружу не уходят ни серийники, ни адреса, ни имена пользователей, ни сырая
телеметрия. Траппер не шифруется, поэтому при не-локальном адресе J-Space предупреждает
об этом в журнале.

## Ограничения демо-версии

Это демо-версия: она показывает продукт целиком, но принимает **до 3
компьютеров** — `/api/v1/ingest` отвечает `403` сверх лимита.

Публичный репозиторий — ещё и срез рабочего дерева, из которого убрана механика
развёртывания в конкретной сети автора: установщик агента с настройкой ACL,
пакеты автообновления парка и справочник организаций.

- **Автообновление агентов** — сервер отдаёт заглушку «пакета нет»; обновлять
  агентов можно тем же установщиком вручную.
- **Справочник организаций** — расшифровка кодов организаций и подразделений
  в человеческие названия; коды работают, названия остаются на вашей стороне.
